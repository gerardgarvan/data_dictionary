(D-08) all live here and must be exact.

REVISION NOTE (review round 1): the original D-08 rule summed all non-N_DISTINCT rows, which would
add MEAN/SD/MIN/MAX into the total and fail every correct numeric variable. Reconciliation is now
class-specific. The schema separates the row identifier (stat) from the category text (level) and
from numeric statistics (value), so truncation, reserved-word collisions and counts-vs-statistics
ambiguity are removed. Phase 7 has not been built, so the schema change costs nothing now;
06-CONTEXT.md is updated in Task 2 to match.

<decisions>
D-02 two percents: pct_total = n/&_p6_total*100 on LEVEL, OTHER, MISSING, N, N_MISSING rows;
  pct_nonmiss = n/n_nonmiss*100 on LEVEL and OTHER rows only (blank on MISSING, N_DISTINCT, STAT rows).
  Compute from counts; do not use PROC FREQ PERCENT.
D-03 HIGH_CARD order: sort_order 0=N_DISTINCT (n = distinct non-missing count); 1..10 top-10 LEVEL
  rows ordered by n desc, then level asc (deterministic tie-break, also decides who makes the top 10);
  11=OTHER (n = sum of non-missing levels ranked >10; always present because HIGH_CARD has >=21
  levels); 99=MISSING (always present, n may be 0).
LOW_CARD order: LEVEL rows sort_order 1..k by n desc, then level asc; MISSING sort_order 99, always present.
CONT_NUM/DATE order: N=1, N_MISSING=2, MEAN=3, SD=4, MEDIAN=5, Q1=6, Q3=7, MIN=8, MAX=9.
D-04 small_cell_flag $1: 'Y' if 1<=n<=10, else 'N', on LEVEL/OTHER/MISSING rows; blank on N_DISTINCT
  and all STAT rows. (Amends the earlier "n<11" wording so an empty MISSING row is not flagged.)
  Open question for sign-off, record in SUMMARY: MIN/MAX can disclose a single person's value.
D-06 DATE: same nine stats as CONT_NUM; display_format and date_kind on every row of the variable.
  SD is a duration (days/seconds), so Phase 7 must not apply display_format to SD — note in CONTEXT.
D-07 100% missing (n_nonmissing = 0, any class including DATE): exactly one row: stat='MISSING',
  n=&_p6_total, pct_total=100, pct_nonmiss=., sort_order=99, small_cell_flag per D-04;
  var_class/date_kind/display_format kept from the classifier. Branch on this BEFORE PROC MEANS so
  all-missing numerics never reach it.
D-08 reconciliation (per variable, hard stop):
  - LOW_CARD:  sum(n where stat in ('LEVEL','MISSING')) = &_p6_total
  - HIGH_CARD: sum(n where stat in ('LEVEL','OTHER','MISSING')) = &_p6_total;
               count(LEVEL rows) = 10; N_DISTINCT n = classifier n_distinct
  - CONT_NUM/DATE: n(N) + n(N_MISSING) = &_p6_total
  - D-07 variables: single MISSING row with n = &_p6_total
  - Set check: the distinct variables in the output = work._p6_vars exactly (count = &_p6_nv,
    no extras, none missing).
</decisions>

<pitfalls>
PROC FREQ OUT= gives COUNT and PERCENT columns and is more stable than ODS OUTPUT (RESEARCH Pitfall 1).
  Each TABLES statement takes its own OUT=.
MISSING option required or missing row/denominator wrong (Pitfall 2/6).
1,297 vars: one PROC MEANS with all non-all-missing CONT_NUM+DATE vars in a single VAR statement;
  batch LOW_CARD/HIGH_CARD TABLES statements ~100 per generated PROC FREQ (Pitfall 3).
No CALL EXECUTE — DATA _NULL_ FILE= + %include only (C24). Generated files are written with FILE
  (never MOD) and named with &family so families don't overwrite each other's includes.
No PROC APPEND FORCE: a single %_p6_attrib macro emits the ATTRIB/LENGTH block; every piece is
  normalised through a DATA step using it before appending, so attributes always match.
Character values from wlatin1 sources (e.g. ß/á in Base_Procedure_1) are UTF-8 in this session;
  the CSV must be written through a FILENAME with encoding='utf-8' (Phase 5 hit 0xDF decode errors).
</pitfalls>
