<objective>
Build the foundation of the `%pdd_profile` engine: Section 0 utility macros plus variable
classification. After this plan, `06_profile_macros.sas` can load a dataset's variable roster,
exclude non-substantive variables, and assign each surviving variable one of four var_class
tiers (DATE, LOW_CARD, CONT_NUM, HIGH_CARD) into a work roster that later computation macros consume.

Purpose: Classification is the gate that decides which statistics each variable gets. Getting
precedence and exclusions right here is what makes the engine reusable across all seven families.
Output: `sas/06_profile_macros.sas` Section 0 (utilities) + `%p6_preflight` + `%p6_classify_vars`.

REVISION NOTE (review round 1): namespaced utilities; explicit failure contract (a %return in
%p6_fail_out does NOT unwind callers); single-pass NLEVELS distinct counting (Phase 5 removed 1,297
per-variable full scans for the same reason); prefix= actually filters; name_map column locked and
mandatory; date-format family list extended with exact matching; date sub-type recorded.
</objective>

FAILURE CONTRACT (applies to every macro in this file and plan 02):
  1. %p6_fail_out sets p6_fail=1 (test mode) or aborts (production). In test mode %return only
     leaves %p6_fail_out itself.
  2. Therefore EVERY caller checks `%if &p6_fail=1 %then %return;` immediately after any call that
     can fail (including %p6_assert_rowcount and every sub-macro), before doing further work.
  3. Messages are stored quoted: %let p6_fail_msg=%superq(msg); and written with %superq.
  4. %_p6_ok(section=) is the standard post-step guard; it calls %p6_fail_out when
     &p6_fail=1 already, obs=0, or &syserr>4.
</patterns>

       (or NLevels minus missing levels when NNonMissLevels is absent) as n_distinct.
       Assert every work._p6_meta variable got exactly one n_distinct row (else %p6_fail_out).
       Write the generated file with FILE ... (not MOD) so a rerun never appends (Phase 5 lesson).

           dates:     DATE DAY DDMMYY DDMMYYB DDMMYYC DDMMYYD DDMMYYN DDMMYYP DDMMYYS MMDDYY MMDDYYB

              value lies in the plausible SAS-date range -3653 to 36525 (1950–2060), checked with ONE
              PROC MEANS min/max over all such candidates together; when it does
              not, classify by cardinality instead and log a NOTE naming the variable ).
         DATE applies even when n_distinct <= 20 (D-06: dates keep DATE tier).
